## EP01, Identity and access

### US-UC08, UC-08 Authenticate

`module:auth`, **X**, actor **Org Manager, Org Operator, TrekLink Staff, TrekLink Admin**, priority **High**, **3** points, **Sprint 3 (W7 to W8)**, status **Backlog**, baseline **yes**, week 3 UC-21

**Jira**: `TK-121`, **branch**: `feat/TK-121-<short-desc>`

**Owner**: Lâm Phi Long (LongLP), secondary Nguyễn Ngọc Long (LongNN), **reviewer**: Đỗ Đăng Khoa (Khoa)

**User story**: As an Org Manager, Org Operator, TrekLink Staff or TrekLink Admin, I want to log in, renew the session silently and log out.

**Acceptance criteria**:

1. FR-AUTH-01: WHEN a mutating request is received, the system SHALL require both a valid JWT and a CASL policy that permits the action, and SHALL return 401 or 403 in the standard envelope otherwise.
2. FR-AUTH-02: WHEN valid credentials are submitted, the system SHALL issue a short-lived access token and a refresh token; IF credentials are invalid, THEN the system SHALL return 401 without revealing which field was wrong.
3. FR-AUTH-03: WHEN a valid refresh token is presented, the system SHALL issue a new access token and rotate the refresh token; IF a rotated refresh token is reused, THEN the system SHALL revoke the whole token family.
4. FR-AUTH-04: WHEN a user logs out, the system SHALL revoke the presented refresh token immediately.
5. FR-AUTH-08: The system SHALL record every authentication event with actor, event type, IP and UTC time, append-only, and SHALL NOT store an attempted password in any form.
6. Alternatives and exceptions: Wrong credentials: MSG09. Reused refresh token: the token family is revoked.
